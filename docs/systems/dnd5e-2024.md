# 龙与地下城 · DND 5E 2024

身份：`dnd5e-2024 / 2024`。世界为 ManualTable，角色的数值位于 `ManualActor.dnd: DndCharacter`。`fields` 主要用于通用显示／扩展，不应另存一套相冲突的 DND 生命值。

## 角色字段分组

| 分组 | 字段 | 说明 |
| --- | --- | --- |
| 身份 | version、kind、side、level、classes、species、background、feats、monster | kind为pc/monster；side为party/hostile/neutral；classes保存每职业等级与子职 |
| 属性与检定 | abilities、skills、saves、skillBonuses、saveBonuses、proficiency、initiative | 属性键str/dex/con/int/wis/cha；skills的值按引擎熟练语义，不是任意总加值 |
| 防御与移动 | ac、speed、hp、maxHp、tempHp、hitDice | 当前基础speed按尺；其他移动模式经对应资料与效果计算 |
| 法术 | spellAbility、spells、slots、spellSources、pact、spellbook、preparation | 已知、准备、法术书、契约法术位不能互相代替 |
| 装备 | weapons、armor、shield、attacks、multiattacks、inventory、currency、training | attacks为可执行攻击参数；物品目录ID与持有实例ID不同 |
| 资源 | resources | 每池max/used/refresh；refresh为short/long/manual |
| 状态 | conditions、exhaustion、resistances、immunities、conditionImmunities、vulnerabilities | 伤害免疫和状态免疫分开 |
| 濒死与施法 | death、concentration、effects、sorcery | 专注引用与持续效果实例需要一致 |
| 成长 | experience、advancement、abilityGeneration | 经验制／里程碑；保留属性生成方式 |
| 扩展运行态 | hiding、bloodiedOverride、load、damageTaken | 不能仅改显示字段影响结算 |

每个子字段、可选性、枚举：[DndCharacter](../../reference/packages/contracts/src/dnd.md)、[DndActiveEffect](../../reference/packages/contracts/src/dnd-effects.md)、[魔法场](../../reference/packages/contracts/src/dnd-magic-fields.md)、[施法状态](../../reference/packages/contracts/src/dnd-magic.md)。

## 创建、升级与导入

使用规则引擎的建卡、兼职、选择与装备接口生成角色，再通过 `DndCreationAction` 或 ActorFile 导入。不要把等级+1就视为完成升级；职业级别、生命骰、子职、专长、选法术、准备和资源上限要一并完成。

入口：[creation](../../reference/packages/rules-engine/src/dnd/creation.md)、[creation-choices](../../reference/packages/rules-engine/src/dnd/creation-choices.md)、[progression](../../reference/packages/rules-engine/src/dnd/progression.md)、[multiclass](../../reference/packages/rules-engine/src/dnd/multiclass.md)、[TableAction](../../reference/apps/desktop/src/tabletop/model.md)。

## 战斗命令与等待流程

`{kind:'dnd',intent:DndIntent}` 通过 GM 事务执行。DndBattle 的 round、turn、order、ended 记录当前先攻；DndTurn 的 action、bonus、reaction、movement、attacks、slotSpent 等分别记录预算。pending 与决策门保存需要谁回答、可选目标或落点；玩家不能替不受控角色回答。

攻击、施法、反应、额外攻击、传送、持续区域与专注不是一次随意扣数值。使用完整意图分支，等待反制／护盾／机会攻击等队列结束后再推进回合。类型表列出所有 DndIntent 参数，不要把 UI 标签直接当 intent.type。

法术 `DndAdjudication` 是尚未完整执行或需要语义裁定的明确流程；`DndAdjudicationResult` 记录行动费用、是否消耗、资源池费用、伤害／治疗／临时生命／状态。日志应说明人工部分，不能把目录中存在的法术全部标成已自动化。

## 状态与持续效果

状态枚举有14项：blinded、charmed、deafened、frightened、grappled、incapacitated、invisible、paralyzed、petrified、poisoned、prone、restrained、stunned、unconscious。bloodied、dead及负重状态是另外的派生／扩展状态，不能塞进DndCondition。

持续效果保存来源、目标、期限、触发、压制与解除关系。非专注法术不应清空已有专注；同名一次性修正要按执行器处理。区域视觉、范围预览、实际命中和伤害结算需一致。二维高度同时参与范围判断，见 [高度](../authoring/scenes-and-elevation.md)。

## 休整与经验

休整请求保存requesterId、votes、hitDice；生命骰方案按角色记录，不能把所有角色资源无条件刷新。普通资源按refresh口径恢复。经验和成长方式属于角色，战斗结束、经验分配与清理先攻是操作流程，不能通过删除战斗字段伪造已经发奖。

## 扩展与当前覆盖

咒火术法使用自己的选择、资源和持续效果字段，不能仅增加一段法术说明。目录、审计记录与执行器是三层。源码核对记录对391个法术有拆解，但当时只有74项存在部分执行路径；数量可随后续源码变化，不能据此宣称完整5R自动化。本版目录索引保留资源定位，实际能力以执行器及客户端提示为准。
