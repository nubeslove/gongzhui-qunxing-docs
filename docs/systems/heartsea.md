# 梦旅心海

显示名称为梦旅心海，稳定身份仍是 `otherworld-journey / 0.1-editorial.1`。世界使用ManualTable。心海是基于5R的独立扩展，不能替换成原版职业卡或自动套用原版所有法术位与职业成长。

## 角色与字符串字段

角色用ManualActor。心海专有数据在fields；值均为字符串，包括数字。

| 键 | 约束／用途 |
| --- | --- |
| `heartsea.version` | `'1'`，启用心海字段校验 |
| `heartsea.kind` | 人物类型的叙事标记 |
| `heartsea.class` | 心铸者／逐影者／灵术师／引航师／星枢师／契灵师 |
| `heartsea.level` | 1–20整数 |
| `heartsea.primary` | 心铸者的主属性选择；其余职业按自身规定读取 |
| `heartsea.pp` | 当前灵能，0–9,999 |
| `heartsea.capacityBonus` | 容量额外修正，0–50 |
| `heartsea.affinity` | 0–5爱心；未建立／初识／熟悉／亲近／深厚／羁绊 |
| `heartsea.balance` | -10至10有符号天平；不是两个独立资源池 |
| `heartsea.relation.忠诚/亲近/认同/服从/依赖/渴求` | 每轴0–10，六轴独立 |
| `heartsea.specialty.label.0` … `.5` | 用户定义轴名，每项≤20字符 |
| `heartsea.specialty.value.0` … `.5` | 每轴0–10；不预设内容或效果 |
| `力量/敏捷/体质/智力/感知/魅力` | 1–30；表现名称可以是躯力／身法／体魄／知性／灵觉／意志 |
| `生命值/生命值上限/护甲等级 AC` | 0–9,999／1–9,999／0–50 |
| `Token` | 棋子素材路径 |
| `立绘 / 立绘·半血 / 立绘·濒死` | 三种可由GM上传的形象素材 |

校验器：[heartsea](../../reference/packages/contracts/src/heartsea.md)。衍生参数：[characters](../../reference/apps/desktop/src/heartsea/characters.md)。`heartseaStats`计算等级、熟练、职业主属性、DC、攻击、容量和灵能上限；当前灵能不能误当上限。

关系雷达图、爱心和天平只是叙事数据。它们不会自动产生战斗加值，也不通过六轴相加自动计算好感。特长六轴由GM自行命名和填写。

## 地图与演出

`story.atlas`保存现实、学院、幻梦境以及后续梦境分支。层级图集不替代实际地图：需要站位、调查范围或战斗时切到场景画布。心海有二维场景、棋子、GM地图编辑与战斗先攻入口；不是只有视觉小说界面。

`stage.ambience = reverie`为“旖旎之梦”粉红主题与爱心／薄雾效果，遵循减少动态效果偏好；不生成剧情、不改关系、不改变结算。台本、登场、台词及条件同通用StoryStage。

生命状态自动选择满血／半血／濒死立绘；缺差分回退普通立绘。Token修改可跟随没有单独覆盖图片的同角色棋子，不能覆盖GM手工指定的场景图片。

## 战斗支持的实际程度

使用心海自身角色记录、通用移动、先攻和已表达的资源能力。原版DND职业执行器不能因为都是5R基础就自动接管心铸者、灵术或使徒能力。当前资料和演出、图集、场景已接入，不代表完整心海逐项战斗自动化完成。准备新能力时记录动作、目标、费用和效果，明确哪些经过通用效果节点，哪些由GM裁定。

## 碧蓝航线UX扩展

UX是心海世界资源包，包ID `heartsea-azur-ux`，不是另一个GameSystemId。当前加入命令为 `{kind:'heartsea.content',pack:'azur-ux'}`，仅心海GM可执行。安装追加缺少资源与图集，不应覆盖同ID已有改稿。

舰装规则、双身份故事和舰娘叙事必须继续使用心海／DND式机制表达，不能把另一游戏的评级字母当攻击加值。指挥官与舰娘身份切换不能凭空补满共用生命、资源或专注。现有UX规则资源有部分GM可见说明，不能把全部内容直接发给玩家。

本公共库不转载UX设定集或私人模组剧情。作者应在有权使用的本地资料中制作自己的模组；接口结构、示例演员与世界图集足以提供格式参考。
